1. Object Orientation & Models (Lecture 1)

  • Object Orientation (OO) = a technique in which we visualize a programming problem in the form of objects and their interactions, just like real life. (Problem ko asli duniya ki cheezon ki tarah sochna.)
  • Model = an abstraction of something real or conceptual. We need models to understand an aspect of reality before building it. Examples: highway maps, architectural models.
  • OO Model = shows several interacting objects to describe a system. Example: objects Ali, Car, House, Tree; interactions: Ali lives-in House, Ali drives Car.
  • Object = a thing having state (attributes / data members) and behavior (operations / member functions), plus a unique identity.
  • Ali → attributes: Name, Age; behavior: Walks, Eats. Identified by name.
  • Car → attributes: Color, Model; behavior: Accelerate, Start, Change Gear. Identified by registration number.
  • Tangible objects = physical, can be seen/touched (Ali, Car, House).
  • Intangible (conceptual) objects = cannot be touched (Time, Date). We assign them our own generated unique ID.
  • Finding objects: in a problem description, nouns are candidates for objects.
  • Advantages of OO: closer to real life → easier to develop; all information of an object is stored inside the object itself and hidden from the outside world; it can only be manipulated by the object itself.

Exam points / traps - Object ke teen pehlu yaad rakho: identity, state, behavior — MCQ favourite. - "Model is an abstraction" — model asal cheez nahi hoti, us ki simplified representation hoti hai. - Not every noun becomes an object; some objects in a scenario have no role in the implementation (e.g. school parking in a school system).

2. Information Hiding, Encapsulation, Interface (Lecture 2)

  • Information Hiding = the internal details (data + implementation) of an object are hidden from the outside world; only the object itself can manipulate them.
  • Advantages: (1) simplifies the OO model, (2) acts as a barrier against change propagation — implementation change karne se model/users affect nahi hote.
  • It is achieved using Encapsulation and Abstraction.
  • Encapsulation = "we have enclosed all the characteristics of an object in the object itself." Data and behavior are tightly coupled inside the object.
  • Advantages: simplicity & clarity, low complexity, better understanding.
  • Interface = the list of operations/functions an object offers to the outside world (what it can do). An object may have more than one interface.
  • Implementation = the internal working — how those operations are actually done (data structures + mechanisms).
  • Example (car gear box): data structure = mechanical structure of gear box; functionality = mechanism to change gear. Driver uses a standard interface (steering, gear lever) and can drive any car without knowing its engine.
  • Separation of Interface & Implementation = interface shown to the world is independent of the internal implementation, so implementation can change without affecting users.
  • Messages = objects communicate by sending messages (stimuli) — i.e. invoking an operation on the target object. The messages an object can receive depend on its interface. Example: Person sends message "stop" to Car by applying brakes.

Exam points / traps - Encapsulation vs Information Hiding: encapsulation is the mechanism (band karna), information hiding is the result/principle (chhupana). Dono related hain lekin same nahi. - Interface = what, Implementation = how. Ye pair har dafa paper mein aata hai.

3. Abstraction & Classes (Lecture 3)

  • Abstraction = "Capture only those details about an object that are relevant to the current perspective." It is a way to cope with complexity by simplifying things.
  • Example: Ali as a student → Roll No, CGPA, Year of Study, Study, GiveExam. Ali as a teacher → Employee ID, Designation, Salary, DeliverLecture. Same object, different perspective, different details.
  • Cat: ordinary view (legs, tail) vs surgeon's view (skeleton, heart, kidney). Car: driver's view vs engineer's view.
  • Advantages: helps solve problems in OO way by hiding irrelevant detail; focusing on one perspective gives freedom to change other aspects later.
  • Abstraction also helps achieve information hiding (show relevant, hide the rest).
  • Class = a sketch / prototype / map from which objects are created. All objects of the same class have identical characteristics (same information structure and behavior) but their own data values.
  • Ali, Anam, Sohail are instances (objects) of class Student.
  • Class = type; Object = instance of that type.

Comparison — Abstraction vs Encapsulation

Abstraction Encapsulation
Focus Only relevant details shown (perspective) Data + functions bound together in one unit
Level Design level (what to show) Implementation level (how to bind/hide)
Roman Urdu Sirf kaam ki cheez dikhao Sab kuch aik dabbe mein band karo

Exam points / traps - Abstraction ka keyword hai "relevant to current perspective" — definition mein ye phrase lazmi likhna. - Class aur object ka farq: class is a blueprint, object is a real instance. "Identical characteristics, own data" — ye line MCQ hai.

4. Inheritance — Concepts (Lectures 3–4)

  • Inheritance = a class (derived/child) acquires the characteristics (data + behavior) of another class (base/parent). Biggest benefit: reuse.
  • Three purposes/views of inheritance: 1. Generalization — common characteristics of several classes are extracted into a general superclass. (Neeche se oopar: Student + Teacher → Person.) 2. Sub-typing / Extension — derived class adds new characteristics to the inherited ones (extends the base). 3. Specialization / Restriction — derived class restricts or modifies inherited behavior for a specific purpose.
  • Overriding = derived class redefines a function already defined in the base class (same name/signature, new body). Used for specialization, extension, restriction, and performance.
  • Abstract class = represents an abstract concept; it is a general class meant to be inherited, cannot be used to create objects directly (concept level, e.g. Shape, Animal).
  • Concrete class = represents a concrete concept; objects can be created from it (e.g. Circle, Student).

Exam points / traps - Generalization = bottom-up (common cheezein oopar wali class mein); Specialization = top-down. - Abstract class ka object nahi banta — ye sab se common trap hai. - Overriding (inheritance, runtime concept) ≠ Overloading (same name, different parameters) — comparison neeche bhi hai.

5. Object Relationships & UML Notation (Lecture 5)

5.1 Simple Association

  • Association = the weakest link between objects; a reference by which one object interacts with another. There is no intrinsic (ownership) relationship. Examples: Ali lives-in House, Ali drives Car, Employee works-for Company, Customer gets cash from Cashier.
  • By navigation (direction):
  • One-way association — navigate in one direction only; shown by a line with an arrow towards the server object.
  • Two-way association — navigate in both directions; shown by a plain line (no arrow). Example: friend (Yasir ↔ Ali).
  • By number of classes (arity):
  • Binary — exactly 2 classes (line/arrow between them).
  • Ternary — exactly 3 classes; shown by a diamond connected to the three classes (Student–Teacher–Course).
  • N-ary — 3 or more classes; practical examples are very rare.
  • Multiplicity / cardinality is written at the ends: 1, * (many), e.g. Ali 1 —— drives —— * Car (one Ali, many cars); Employee * —— 1 Company.

5.2 Composition (strong "part-of")

  • A whole object is made of part objects (Ali is composed of Head, Arms...; Car is composed of Engine, Wheels).
  • Filled diamond (◆) at the whole/composer end.
  • Strong ownership: parts are created and destroyed with the whole; a part belongs to only one whole at a time. Lifetime of parts depends on the whole.

5.3 Aggregation (weak "has-a")

  • A whole object contains other objects, but they have their own independent life (e.g. a Department has Teachers; department band ho jaye to teachers phir bhi exist karte hain).
  • Hollow diamond (◇) at the whole end.
  • Parts can be shared between wholes and can exist before/after the whole.

UML Notation Summary (Lecture 5 + 22) — ⭐ paper mein diagram lazmi aata hai

Relationship Line style Meaning
Association Solid line (arrow = one-way navigation) objects interact / know each other
Composition Line with filled diamond ◆ at whole end strong part-of, same lifetime
Aggregation Line with hollow diamond ◇ at whole end weak has-a, independent lifetime
Inheritance (Generalization) Line with hollow triangle △ pointing to parent "is-a"
Class box Rectangle: Name / attributes / operations (3 compartments) - private, + public, # protected

5.4 Multiple Inheritance (Lecture 5)

  • One class derived from two or more base classes. Example: class Mermaid : public Woman, public Fish { }; — Mermaid can walk() (Woman) and swim() (Fish). Amphibious Vehicle ← LandVehicle + WaterVehicle.
  • Advantage: more reuse, less redundant code.
  • Problems (exam favourite): increased complexity, reduced understanding, duplicate features → ambiguity. If both Woman and Fish have eat(), which one does Mermaid inherit?
  • Solution: override eat() in Mermaid and explicitly call the desired parent version using scope resolution: Woman::eat();

Comparison — Association vs Aggregation vs Composition

Association Aggregation Composition
Strength Weakest Weak Strong
Ownership None Has-a (no ownership of life) Part-of (owns parts)
Lifetime of parts Independent Independent Depends on whole
Diamond None (plain line) Hollow ◇ Filled ◆
Example Ali drives Car Department has Teachers Car has Engine

Exam points / traps - Diamond hamesha whole wali taraf hota hai, part wali taraf nahi — diagram trap. - Composition mein part do wholes ke darmiyan share nahi ho sakta; aggregation mein ho sakta hai. - Multiplicity * ka matlab "many" hai, 1 ka matlab exactly one.

6. Class Compatibility & Polymorphism — Intro (Lecture 6)

  • Class compatibility = an object of a derived class can be used wherever an object of the base class is expected, because the derived class has all the characteristics of the base (is-a relationship).
  • Polymorphism = "many forms" — the same message/operation produces different behavior depending on the object that receives it. (Aik hi call, mukhtalif jawab.)
  • In OO model: a general class defines an operation (e.g. draw() in Shape); each derived class (Circle, Triangle, Line) implements it in its own way. The client sends the same message to all.
  • Graphic editor example: editor holds different shapes and calls draw() on each — correct version runs for each shape.
  • Advantages of polymorphism: simplifies code (no type-checking chains), new derived classes can be added without changing existing client code (extensibility).

Exam points / traps - Polymorphism ki working example graphic editor / shapes wala hai — subjective mein yehi manga jata hai. - Compatibility sirf derived → base direction mein hoti hai (Student object Person ki jagah chal sakta hai; Person object Student ki jagah nahi).

7. Classes in C++ (Lecture 7)

  • In C++, a class is a user-defined type — once defined, it can be used like built-in types (int, float).
  • Defining a class = defining a new type (abstraction in C++): we bundle the data and the functions that operate on it.
class Student {
private:
    int rollNo;
    float cgpa;
public:
    void setRollNo(int r) { rollNo = r; }
    int  getRollNo()      { return rollNo; }
};
Student s1;            // s1 is an object (instance) of class Student
s1.setRollNo(101);     // accessing member through object: object.function()
  • Access specifiers:
  • private — accessible only inside the class (default for class members).
  • public — accessible from anywhere; forms the object's interface.
  • Data members are normally kept private (information hiding); member functions that provide services are public.
  • Members are accessed with the dot operator object.member.

Exam points / traps - Class mein default access private hota hai (struct mein public) — classic MCQ. - Object banana = constructor call hota hai (neeche dekho).

8. Member Functions & Constructors (Lecture 8)

  • Member functions can be defined inside the class body, or outside using the scope resolution operator:
void Student::setRollNo(int r) { rollNo = r; }   // outside definition
  • Inline functions: a member function defined inside the class body is automatically inline; outside functions can be made inline with the inline keyword. Inline = compiler replaces the call with the function code (saves call overhead) — suitable for small functions only.
  • Constructor = a special member function that is called automatically when an object is created; used to initialize the object.
  • Properties: same name as the class; no return type (not even void); cannot be called explicitly like normal functions; usually public.
  • Default constructor = constructor with no parameters (or all default parameters). If we define no constructor, the compiler provides one. If we define any constructor, the compiler does not provide the default one.
  • Constructor overloading = multiple constructors with different parameter lists (e.g. Student(), Student(int), Student(int, float)).
  • Copy constructor = constructor that creates a new object as a copy of an existing object of the same class:
Student(const Student & s);   // takes reference to object of same class
  • Called when: object is initialized with another object (Student s2 = s1;), object is passed by value to a function, object is returned by value from a function.
  • If we don't write it, the compiler generates one that does member-by-member (shallow) copy.

Exam points / traps - Constructor ka return type nahi hota — agar option mein void Student() aaye to woh constructor nahi, ghalat hai. - Student s2 = s1; — ye assignment nahi, copy constructor hai kyun ke s2 pehli dafa ban raha hai. (Initialization vs assignment — Lecture 11 bhi dekho.)

9. Shallow vs Deep Copy, Destructor, Accessors, this (Lecture 9)

  • Shallow copy = member-by-member copy; if a member is a pointer, only the address is copied → both objects point to the same memory. Problem: changing one object's data changes the other's; both destructors may free the same memory (double deletion crash).
  • Deep copy = copy the actual data pointed to, into newly allocated memory, so each object has its own copy. Achieved by writing our own copy constructor (and assignment operator) for classes with pointer members / dynamic memory.
  • Important points about copy constructor:
  • Parameter must be a reference (const Student &) — by-value parameter would itself need a copy constructor → infinite recursion.
  • Compiler-generated copy constructor is enough only when the class has no dynamically allocated memory.
  • Destructor = special function called automatically when an object is destroyed (goes out of scope / delete); used to release resources (e.g. delete[] dynamic memory).
  • Name = ~ClassName(); no parameters, no return type; only one destructor per class (cannot be overloaded).
  • Accessor functions = getters (read a data member) and setters/mutators (write a data member with validation). They protect private data while giving controlled access.
  • this pointer = every non-static member function receives a hidden pointer this that points to the object through which the function was called. this->rollNo is the same as rollNo inside a member function.

Comparison — Shallow vs Deep Copy

Shallow Copy Deep Copy
Pointer members Address copied Data copied into new memory
Memory shared? Yes — both objects share data No — separate copies
Risk Double deletion, unwanted changes Safe
Who provides Compiler's default copy ctor Programmer-written copy ctor

Exam points / traps - "Copy constructor ka parameter reference kyun hota hai?" — ye subjective ka pakka sawal hai (warna infinite loop/recursion). - Destructor overload nahi ho sakta; constructor ho sakta hai.

10. this Pointer & const Member Functions (Lecture 10)

  • Uses of this: 1. To resolve name conflicts when a parameter has the same name as a data member: this->x = x; 2. To return the object itself from a member function (return *this;) — enables chaining of function calls. 3. Compiler uses it internally to identify which object's data is being accessed.
  • Separation of interface & implementation in C++: class declaration (interface) goes in a header file (.h), function definitions (implementation) in a .cpp file — user sirf interface dekhta hai.
  • const member functions = functions that cannot modify the data members of the object; declared with const after the parameter list:
int getRollNo() const { return rollNo; }   // promises not to change the object
  • Only const member functions can be called on const objects.
  • Inside a const member function, this becomes a pointer to const object, so data members cannot be changed through it.
  • Handout example throughout Lectures 10–11: Complex number class (real, img) used to demonstrate const functions and operators.

Exam points / traps - const object sirf const member functions call kar sakta hai — agar non-const function call ki to compile error. - const function ke andar data member change karna = compile error (MCQ trap).

11. Initializer List, const Objects, Static Members (Lectures 11–12)

  • Initialization vs Assignment:
  • Initialization = value given at the time of creation (int x = 5;, copy constructor case).
  • Assignment = value given to an already existing object (x = 5;, assignment operator case).
  • Member Initializer List = values given to data members before the constructor body runs:
Student::Student(int r, float c) : rollNo(r), cgpa(c) { }
  • Must be used when a data member is: (1) const, (2) a reference, (3) an object of another class that has no default constructor. (Ye teen cases subjective mein lazmi aate hain.)
  • Member objects are initialized in the order they are declared in the class, not the order in the list.
  • const objects = const Student s; — their data cannot change after creation; only const member functions can be called on them.
  • Static data member = a member shared by all objects of the class — only one copy exists for the whole class (e.g. count of students).
  • Declared inside the class, defined/initialized outside the class: int Student::count = 0;
  • It is created when the program starts and lives for the whole program (not tied to any object).
  • Accessed as Student::count or through any object.
  • Static member function = belongs to the class, called as Student::getCount(); without an object.
  • It can access only static data members (and other static functions) — because it has no this pointer.
  • Global variable vs static member: a global is accessible everywhere in the program (risky, no hiding); a static member is inside the class scope, so access can be controlled (private static + public static getter).
  • Array of objects = Student s[10]; — the default constructor is called for every element; is liye default constructor lazmi chahiye hota hai.

Exam points / traps - Static member function mein this nahi hota → non-static member access = error. Pakka MCQ. - Static data member ki definition class ke bahir likhi jati hai; sirf declaration andar hoti hai. - Initializer list ke teen "must" cases ratta maar lo.

12. Pointers to Objects & the new Operator (Lecture 13)

  • Pointer to object: Student *ptr = &s1; — members accessed with arrow operator: ptr->getRollNo();
  • new operator creates an object dynamically (on heap) and returns its pointer. The new operation is a combination of two steps: 1. Memory allocation for the object. 2. Constructor call to initialize that memory. cpp Student *p = new Student(101, 3.5); // allocate + construct delete p; // destructor call + memory freed
  • delete does the reverse: destructor is called first, then memory is released. new[]/delete[] are used for arrays of objects.
  • Handout case study: complete code of the Date class (day/month/year with setters/getters and validation).

Exam points / traps - "new ke do steps" (allocation + construction) aur "delete ke do steps" (destruction + deallocation) — order ulta hota hai, yehi trap hai. - new se bana object khud destroy nahi hota — delete na kiya to memory leak.

13. Composition & Aggregation in C++ (Lectures 14–15)

  • Composition in C++ = a class contains objects of other classes as data members (by value):
class Car {
    Engine engine;        // member object — composition
    Wheel wheels[4];
};
  • Member objects are constructed before the containing object's constructor body runs (in declaration order), and destroyed after it, in reverse order.
  • Container constructor passes arguments to member objects through the member initializer list.
  • Aggregation in C++ = a class contains pointers/references to objects that are created outside and passed in:
class Department {
    Teacher *teachers[20];   // aggregated — Department does not own their lifetime
};
  • The whole does not create or destroy the parts; parts can be shared.

Friend Functions (Lecture 15)

  • A friend function is a non-member function that is given access to the private and protected members of a class:
class Student {
    friend void printData(const Student & s);   // declaration inside class
};
  • Properties (exam favourite list):
  • It is not a member function — it is called without an object (printData(s);, not s.printData();).
  • It is declared inside the class with keyword friend, but defined outside without scope resolution.
  • Friendship is not inherited, not transitive (friend of a friend is not a friend), and not mutual/reciprocal unless explicitly declared both ways.
  • A whole class can also be declared friend (friend class X;) — all its member functions become friends.
  • Use sparingly: friends break encapsulation, so they are used only when genuinely needed (e.g. operator overloading with streams).

Exam points / traps - Composition = member object by value; Aggregation = member pointer/reference. Code dekh kar pehchanna paper mein aata hai. - Friend function object ke baghair call hoti hai lekin private data access kar sakti hai — yehi us ki pehchan hai.

14. Operator Overloading (Lectures 16–21)

14.1 Basics (Lecture 16)

  • Operator overloading = giving an existing C++ operator (like +) a new meaning for a user-defined type, so objects can be used naturally: Complex c3 = c1 + c2; instead of c1.Add(c2).
class Complex {
    double real, img;
public:
    Complex operator + (const Complex & c) const {
        Complex t;
        t.real = real + c.real;
        t.img  = img  + c.img;
        return t;
    }
};
  • Rules (⭐ sab se zyada MCQs yahin se):
  • You cannot create new operators; only existing ones can be overloaded.
  • You cannot change an operator's precedence or number of operands (arity) — + binary hai to binary hi rahega.
  • At least one operand must be a user-defined type.
  • Operators that cannot be overloaded: . (member access), .*, :: (scope resolution), ?: (conditional), sizeof.
  • Overloading does not change the operator's meaning for built-in types.
  • When a binary operator is overloaded as a member function, it takes one explicit parameter (the left operand is the calling object, via this). As a friend/non-member, it takes two.

14.2 Assignment Operator = (Lecture 17)

  • The compiler generates a default assignment operator that does member-by-member (shallow) assignment — fine for simple classes, dangerous for classes with dynamic memory (same double-deletion problem as shallow copy).
  • We overload operator= to do deep copy, and it should return a reference to *this so chained assignment works: a = b = c;
String & String::operator = (const String & other) {
    if (this != &other) {          // self-assignment check (Lecture 18)
        delete[] data;             // free old memory
        data = new char[strlen(other.data) + 1];
        strcpy(data, other.data);
    }
    return *this;
}

14.3 Self-Assignment & Other Operators (Lecture 18)

  • Self-assignment problem = a = a; — if we delete[] our own data first, the source data is lost. Solution: check if (this != &other) before deleting, or compare addresses.
  • Other binary operators (-, *, /, +=, -=...) are overloaded with the same pattern as +. Compound operators (+=) modify the calling object and return *this by reference.
  • Friend functions & operator overloading: a friend version is needed when the left operand is not an object of our class (the member version can't be used) — the classic case is stream operators.

14.4 Stream Operators << and >> (Lecture 19)

  • Stream insertion cout << obj; and extraction cin >> obj; — here the left operand is ostream/istream, not our class, so these must be overloaded as non-member (friend) functions:
ostream & operator << (ostream & out, const Complex & c) {
    out << c.real << " + " << c.img << "i";
    return out;                    // return stream → chaining: cout << a << b;
}
istream & operator >> (istream & in, Complex & c) {
    in >> c.real >> c.img;
    return in;
}

(Friend declaration is needed because they access private members.)

14.5 Subscript [] and Function-Call () Operators (Lecture 20)

  • Subscript operator — used to give array-like access with bounds checking:
int & String::operator [] (int index);        // non-const: allows s[0] = 'A';
const int & String::operator [] (int index) const;  // const version for const objects

Returning a reference is essential — tab hi s[2] = 'x'; kaam karega. - Function operator operator() — makes an object callable like a function (function object / functor); it can take any number/type of parameters. Handout example: using () to extract a substring from a String object.

14.6 Unary Operators, ++/-- (Lectures 20–21)

  • Unary operators (-, !, ~) as member functions take no parameter.
  • Prefix vs Postfix ++ (⭐ pakka exam point):
Complex operator ++ ();        // prefix:  ++c  → increment, then return new value
Complex operator ++ (int);     // postfix: c++  → dummy int parameter; return OLD value

The dummy int parameter is the only difference — it is not used, it just tells the compiler "this is postfix".

14.7 Type Conversion (Lecture 21)

  • Basic → User-defined (conversion constructor): a constructor with a single parameter of another type converts that type into our class:
class Complex { public: Complex(double r) { real = r; img = 0; } };
// now: Complex c = 5.5;  works (double → Complex)
  • User-defined → Basic/other (conversion operator): a member function with no return type named after the target type:
operator double() { return real; }   // Complex → double
  • Drawbacks: automatic conversions can cause ambiguity (if both a conversion constructor and a conversion operator can apply, compiler may not decide → error), and they can produce unexpected results — is liye soch samajh kar use karo.

Comparison — Overloading vs Overriding

Overloading Overriding
Where Same class (or scope) Base + derived class
Parameters Must differ Must be same
Return type May differ Same (generally)
Needs inheritance No Yes
Binding Compile time (Concept in midterm; virtual mechanism is Lecture 28)

Exam points / traps (Operator Overloading) - << member function se overload nahi ho sakta jab left operand stream ho — friend lazmi hai. - Postfix ++ mein dummy int sirf pehchan ke liye hai; value purani return hoti hai. - Assignment operator aur copy constructor — dono ka kaam deep copy hai; pointer wali class mein dono khud likhne parte hain (warna shallow copy ke masle). - Operators ki precedence/arity change nahi ho sakti — ye statement MCQ mein true/false ban kar aata hai.

15. Inheritance in C++ (Lecture 22)

  • Syntax:
class Student : public Person {
    // Student (derived/child) inherits from Person (base/parent)
};
  • Inheritance represents the "IS-A" relationship: a Student IS A Person — "derived class IS A kind of base class."
  • UML notation: a line from derived class to base class with a hollow triangle (△) at the base class end.
  • What is inherited: the derived class contains all characteristics (data + functions) of the base class, plus its own new characteristics. In memory, a derived object contains a base-class sub-object inside it.
  • Access rules:
  • public members of base → accessible in derived and through derived objects (with public inheritance).
  • private members of base → are inherited (present in memory) but NOT directly accessible in the derived class — only through base class's public/protected functions. (Information hiding yahan bhi apply hoti hai — common trap: "private members inherit nahi hote" ghalat hai; woh hote hain, bas access nahi hota.)
  • Three modes of inheritance in C++: public, private, protected — mode controls how base members appear in the derived class (tafseel Lectures 26–27 mein hai; midterm mein sirf pehchan rakho: public inheritance hi "is-a" ko sahi represent karti hai aur aam tor par yehi use hoti hai).
  • Constructor/Destructor order (⭐ pakka MCQ):
  • Construction: base class constructor first, then derived class constructor. (Pehle buniyad, phir building.)
  • Destruction: reverse — derived destructor first, then base destructor.
  • Member objects (composition) are constructed before the containing class's constructor body, in declaration order.
  • Base class is initialized from the derived constructor using the member initializer list: Student::Student(...) : Person(...) { }

Exam points / traps (Inheritance) - Constructor order: Base → Derived. Destructor order: Derived → Base. Ye pair har midterm mein aata hai. - class Student : public Person mein public inheritance mode hai, access specifier nahi — dono ka role alag hai. - Private base members derived class mein exist karte hain lekin directly access nahi hote.

Quick One-Page Recap (exam se pehle ye parh lena)

  1. Object = identity + state (data members) + behavior (member functions). Class = blueprint; object = instance.
  2. Encapsulation = data + functions aik unit mein; Information hiding = us ka faida; Interface = what, Implementation = how.
  3. Abstraction = sirf relevant details, current perspective ke mutabiq.
  4. Inheritance ke 3 roop: Generalization (common → base), Extension/Sub-typing (naya add), Specialization/Restriction (modify/restrict). Overriding = derived mein same function dobara define.
  5. Abstract class ka object nahi banta; concrete ka banta hai.
  6. Association (weakest, plain line) < Aggregation (hollow diamond, independent life) < Composition (filled diamond, lifetime bound).
  7. UML: inheritance = hollow triangle parent ki taraf; diamond hamesha whole ki taraf.
  8. Constructor: no return type, object bante hi call; copy constructor ka parameter reference; destructor sirf aik, overload nahi.
  9. Pointer wali class → shallow copy khatarnak → apna copy constructor + assignment operator (deep copy) + self-assignment check.
  10. this = current object ka pointer; static members class ke hain, this static function mein nahi hota.
  11. Initializer list lazmi: const member, reference member, member object without default constructor.
  12. new = allocation + construction; delete = destruction + deallocation.
  13. Friend = non-member, private access, not inherited/transitive/mutual.
  14. Operator overloading: naye operator nahi ban sakte; precedence/arity change nahi; . :: ?: sizeof .* overload nahi hote; <</>> friend se; postfix ++ mein dummy int.
  15. Inheritance: is-a; construction Base → Derived, destruction Derived → Base.
