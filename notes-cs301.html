1. Introduction — What is a Data Structure? (Lecture 1)

Definition: A data structure is a way of organizing and storing data in a computer so that operations on the data can be performed efficiently (fast, with less memory).

Key ideas: - A program = algorithms + data structures. Data ko sahi tareeqay se rakho ge to program khud fast ho jayega. - No single data structure is best for all situations. Ek structure ek kaam mein best hai, doosray mein bekaar. This is the "philosophy" of the course. - Selecting a data structure — steps: (1) analyze the problem, (2) decide the basic operations needed (insert, delete, search…), (3) quantify the resources (time/space) for those operations, (4) pick the structure that best meets those requirements. - Course covers: arrays, lists, linked lists, stacks, queues, trees, (later) graphs, heaps, hashing.

Exam points / traps: - "Data structure philosophy" wala sawal aata hai: there is no data structure that is better than others in all situations. - Efficiency do cheezon se measure hoti hai: time (running time) aur space (memory).

2. Arrays and the List ADT (Lectures 1–2)

Array: Fixed-size collection of same-type elements stored in contiguous (saath saath) memory locations. Indexing se kisi bhi element tak foran access: A[i] ka address = base + i × element size.

List (ADT): An ordered sequence of elements with operations: - add(x) / insert — element shamil karna - remove(x) — element nikalna - find(x) — element dhoondna - next() — current position se aglay element par jana (list has a "current position" concept in VU's implementation) - length(), isEmpty() etc.

Array-based list — analysis (bohat important):

Operation Cost Reason
Access by index O(1) direct address calculation
Find (search a value) O(n) worst case poori list dekhni parti hai
Insert in middle O(n) baqi elements ko shift karna parta hai
Remove from middle O(n) gap band karne ke liye shift karna parta hai
Insert at end O(1) agar jagah khaali ho

Limitations of array list: size pehle se fixed hai — full ho jaye to naya data store nahi ho sakta; insert/remove mein shifting mehngi hai. Yehi limitation linked list ki wajah bani.

Exam points / traps: - ADT ka matlab: sirf what operations hain, how implement hoti hain woh alag baat hai. Same List ADT array se bhi ban sakti hai, linked memory se bhi. - Shifting cost hi array list ka sab se bara exam point hai.

3. Singly Linked List (Lectures 2–4)

Definition: A collection of nodes, where each node has two parts: data and a next pointer (address of the next node). Nodes memory mein scatter hote hain — array ki tarah contiguous nahi hote. Ek head pointer pehle node ko point karta hai; aakhri node ka next = NULL.

head -> [data|next] -> [data|next] -> [data|NULL]

How it works (operations): - Insert at start: new node ka next = head; head = new node. → O(1) - Insert in middle / after a node: pehle woh node dhoondo (traverse), phir do pointers badlo: newNode->next = p->next; p->next = newNode; → search O(n), actual insert O(1) - Delete a node: previous node ka next ko deleted node ke next se jor do, phir memory free karo. → search O(n), delete O(1) - Traverse/Find: head se shuru karke next follow karte jao jab tak NULL ya value na mil jaye. → O(n) - No random access: list[5] nahi kar sakte — 5th element ke liye pehle 4 se guzarna parega.

Pointer steps yaad rakhna (exam mein code/trace aata hai): Insert after node p: pehle newNode->next = p->next (order ulta karoge to baqi list kho jayegi — classic trap!)

Analysis vs array list:

Operation Array List Linked List
Access i-th element O(1) O(n)
Find value O(n) O(n)
Insert/Delete (position known) O(n) shifting O(1) pointer change
Size Fixed Dynamic (grows as needed)
Extra memory None One pointer per node

Exam points / traps: - Linked list mein size ki koi limit nahi (memory tak), lekin har node ke saath pointer ki extra memory lagti hai. - Delete/insert "O(1)" tab kehte hain jab node ka address pehle se maloom ho; dhoondna shamil karo to O(n). - Head par insert/delete special case hota hai — code mein alag handle hota hai.

4. Doubly & Circular Linked Lists + Josephus Problem (Lectures 4–5)

Doubly Linked List: Har node mein three parts: prev pointer, data, next pointer. Dono taraf traverse kar sakte ho. - Faida: kisi node par kharay ho to pichla node foran mil jata hai — delete asaan (previous dhoondna nahi parta). - Nuqsan: har node par ek extra pointer ki memory; insert/delete mein zyada pointers badalne parte hain (4 tak).

Circular Linked List: Aakhri node ka next wapas head ko point karta hai — list gol ghoomti hai, koi NULL end nahi. - Kisi bhi node se shuru karke poori list traverse ho sakti hai. - Faida: end par pohanch kar dobara shuru karna asaan; queue jaise kaam ke liye mufeed.

Josephus Problem (famous example): N log gol ghare (circle) mein kharay hain. Har M-th (e., har 3rd) banda eliminate hota hai, jab tak ek leader reh jaye. Circular list se isay simulate karte hain: current node se M steps chalo, us node ko delete karo, phir wahan se aage continue karo. Handout example: 10 logon mein se leader select kiya gaya. - Trap: elimination ke baad counting wahi se shuru hoti hai jahan se banda nikla tha (next node se).

Exam points: - Doubly list ka delete code doubly pointers ki wajah se lamba hota hai — steps yaad rakho. - Circular list mein traversal rokne ki condition NULL nahi hoti — wapas start node par aana hota hai, warna infinite loop!

5. Abstract Data Type (ADT) (Lecture 5)

Definition: An ADT is a mathematical model of a data structure that defines what operations are allowed, without saying how they are implemented. (Interface alag, implementation alag.)

  • List, Stack, Queue — sab ADTs hain. Har ek ko array se bhi implement kar sakte ho, linked list se bhi.
  • User ko sirf operations dikhte hain; andar ka mechanism chhupa hota hai (data hiding / encapsulation).

Exam point: "ADT implementation se independent hota hai" — yehi is ka sab se bara point hai. Stack array se bano ya linked list se, push/pop ka behavior same rahega.

6. Stack (Lectures 5–6)

Definition: A stack is a LIFO (Last In First Out) structure — jo element sab se aakhir mein gaya, wahi sab se pehle bahir aayega. Real example: plates ka stack, tray stack.

Operations (sirf top par hoti hain): - push(x) — top par element rakhna - pop() — top wala element nikalna (aur return karna) - top() / peek() — top wala element sirf dekhna, nikalna nahi - isEmpty(), isFull() (array implementation mein)

Array implementation: ek array + ek top variable (index of top element, empty par −1).

push(x):  top++; A[top] = x;
pop():    x = A[top]; top--; return x;
  • push/pop dono O(1).
  • Stack overflow: full stack par push karna. Stack underflow: empty stack par pop karna. Dono errors exam mein pooche jate hain.

Linked list implementation: head hi top hota hai — push = insert at head, pop = delete at head. Dono O(1), aur size ki koi fixed limit nahi.

Array vs Linked List implementation (handout ka comparison): - Array: simple, lekin size fixed — overflow ka khatra. - Linked list: dynamic size, lekin har element ke saath pointer ki memory + new/delete ka overhead.

Uses of stack: expression evaluation/conversion, function calls (call stack), undo feature, backtracking, parentheses checking.

Exam points / traps: - Stack mein beech se element nahi nikal sakte — sirf top. - pop() element remove bhi karta hai, top() sirf batata hai — farq yaad rakho.

7. Infix, Prefix, Postfix — Conversion & Evaluation (Lectures 6–8)

Notations: - Infix: operator darmiyan mein — A + B (insaanon ke liye asaan, computer ke liye mushkil — precedence aur parentheses handle karne parte hain) - Postfix (Reverse Polish): operator baad mein — A B + (na parentheses, na precedence ka masla — stack se seedha evaluate hoti hai) - Prefix (Polish): operator pehle — + A B

Operator precedence: ^ (power) sab se zyada, phir * /, phir + -. Parentheses sab par bhaari.

Infix → Postfix conversion (stack algorithm)

Expression ko left se right parho: 1. Operand (A, B, 5…) → seedha output mein likh do. 2. ( → stack par push karo. 3. ) → stack se pop karke output mein likhte jao jab tak ( na aaye; ( ko discard karo. 4. Operator → jab stack top par maujood operator ki precedence zyada ya barabar hai, usay pop karke output mein likho; phir current operator push karo. 5. End par stack ke bache hue operators pop karke output mein likh do.

Worked example: A + B * C → postfix: A B C * + (Because * pehle hoga.) Aur (A + B) * C → A B + C *

Worked example (bigger): A * (B + C) → A B C + *

Postfix evaluation (stack algorithm)

Left se right parho: 1. Operand → stack par push karo. 2. Operator → do operands pop karo (pehla pop = right operand, doosra pop = left operand — order matter karta hai − aur / mein!), result calculate karke push karo. 3. End par stack mein bacha ek hi number = jawab.

Worked example: 5 3 + 2 * → 5 push, 3 push, + → pop 3, pop 5 → 8 push; 2 push; * → 16. Answer = 16.

Exam points / traps (ye section midterm ka favourite hai): - Evaluation mein pop ka order: 8 2 - = 8 − 2 = 6, lekin stack se pehle 2 pop hoga, phir 8. Galti yahin hoti hai. - Conversion mein operands ka order kabhi nahi badalta — sirf operators idhar udhar hote hain. - Equal precedence par left-to-right associativity: A - B - C → A B - C -. - Trace table bana kar practice karo — exam mein poora conversion/evaluation trace aata hai.

8. Function Call Stack, Memory & C++ Support Topics (Lectures 8, 9, 17–19)

Memory organization (program ki memory): Code/text segment, static/global data, stack (function calls, local variables), heap (dynamic memory — new se milti hai).

Function call stack: Jab function call hota hai to us ki information (return address, parameters, local variables) ek activation record / stack frame ki shakal mein stack par push hoti hai. Function khatam ho to frame pop ho jata hai aur control return address par wapas jata hai. - Isi liye recursion kaam karti hai: har recursive call ka apna alag frame, apni alag local variables ki copy. - Call by value: parameter ki copy frame mein banti hai — original change nahi hota. - Call by reference / by pointer: address jata hai — original change ho sakta hai.

C++ Templates: Ek hi code mukhtalif data types ke liye. Jaise Stack<int>, Stack<float> — class ek dafa likho, har type ke liye compiler khud version bana deta hai. Handout mein stack ko template class se implement kiya gaya hai taake kisi bhi type ka stack ban sake.

Reference variables (&): Ek existing variable ka alias (doosra naam). int& r = x; — r aur x ek hi memory hain. - Reference ko declare karte waqt initialize karna lazmi hai; baad mein kisi aur variable ki taraf nahi mor sakte. - Faida: function ko bari object ki copy bhejne ki bajaye reference bhejo — time/memory bachta hai.

const keyword: const parameter/value ko function ke andar change hone se rokta hai. - Best combination (handout ki tip): const Type& parameter — na copy bane (reference ki wajah se) aur na value change ho (const ki wajah se). BST ke interface mein yehi use hua hai.

Exam points / traps: - Reference ≠ pointer: reference ko NULL nahi kar sakte, reseat nahi kar sakte, initialize karna lazmi hai. - Recursion khatam na ho (base case na ho) to stack overflow ho jata hai — frames bharte rehte hain.

9. Queue (Lectures 9–10)

Definition: A queue is a FIFO (First In First Out) structure — jo pehle aaya, wahi pehle jayega. Real example: bank ki line, ticket counter.

Operations: - enqueue(x) — rear (end) par element daalna - dequeue() — front se element nikalna - front() — front wala element dekhna - isEmpty(), isFull()

Array implementation ki problem: Agar front ko aage barhate jao to shuru ki jagah khaali reh jati hai lekin array "full" lagta hai — jagah waste.

Solution — Circular Array (handout ka tareeqa): Array ko gol (circular) samjho — jab rear aakhir par pohanchay aur shuru mein jagah khaali ho to rear wapas index 0 par aa jata hai (wrap around). Index aise barhta hai: rear = (rear + 1) % size. - enqueue/dequeue dono O(1). - Trap: Circular queue mein "full" aur "empty" ko alag pehchanna hota hai — aam tareeqa: ya to ek slot hamesha khaali rakho, ya elements ki count rakho. Warna front == rear dono halaton mein ho sakta hai.

Linked list implementation: front aur rear dono pointers rakho — enqueue rear par (O(1)), dequeue front se (O(1)). Ek hi pointer (sirf front) ho to enqueue O(n) ho jayega — ye exam trap hai.

Uses: simulation models (bank queue — handout ka example), printer jobs, CPU scheduling, BFS (baad mein), keyboard buffer.

Exam points: - Stack vs Queue ka farq lazmi yaad rakho: LIFO vs FIFO; insert/delete dono ends alag (queue) vs ek hi end (stack). - Circular queue ka modulo wala index calculation trace mein aata hai.

10. Priority Queue (Lectures 10–11)

Definition: Aisi queue jahan har element ke saath ek priority hoti hai. Dequeue hamesha sab se zyada priority wala element nikalta hai — line mein pehle aana zaroori nahi. (Hospital emergency, bank mein VIP customer — handout ka bank simulation isi se extend hota hai.)

Implementation choices (trade-off yaad rakho): - Unsorted list/array: enqueue O(1) (bas daal do), lekin dequeue O(n) (poori list mein max priority dhoondna parta hai). - Sorted list: dequeue O(1) (front se max nikal lo), lekin enqueue O(n) (sahi jagah par insert + shifting/pointer work). - (Heap se behtareen implementation final term mein aati hai — midterm mein list wali implementation hi hai.)

Bank simulation (Lecture 10): Customers bank aate hain, tellers ke saamne queue lagti hai; simulation se average waiting time waghera calculate hota hai. Queue data structure real-world events ko model karne ke liye use hota hai — ye "simulation model" ka concept exam mein short question mein aata hai.

Exam point: Priority queue mein FIFO rule toot jata hai — priority FIFO par jeet jati hai. Agar do elements ki priority barabar ho to un ke darmiyan FIFO lagta hai.

11. Trees & Binary Tree Basics (Lectures 11–12)

Tree terminology (definitions lazmi yaad karo): - Tree: nodes ka hierarchical (darja-band) collection; ek khaas node root hota hai. - Parent / Children: node jis se branch nikli = parent; neeche walay = children. Same parent ke children = siblings. - Leaf node: jis ke koi children na hon. Internal node: jis ke kam az kam ek child ho. - Edge/Link: do nodes ko jorne wali line. n nodes wale tree mein hamesha n − 1 edges hoti hain. - Level: root level 0 (ya 1 — handout root ko level 0 se shuru karta hai, question ke context se samajhna); har neeche wali generation +1. - Depth (of tree): sab se gehray leaf ka level = maximum level. - Height (of node): node se neeche sab se lambe path par edges ki tadaad; leaf ki height 0. - Subtree: kisi node ko root maan kar us ke neeche ka poora hissa. - Path / ancestor / descendant: ancestor = node se root tak ke saare nodes; descendant = node ke neeche ke saare nodes.

Binary Tree: Har node ke zyada se zyada 2 children — left child aur right child (dono alag pehchan rakhte hain; sirf ek child ho to left hai ya right, farq parta hai!). - Strictly binary tree: har internal node ke bilkul 2 children (0 ya 2 — 1 wala allowed nahi). - Complete binary tree (handout definition): depth d ki woh strictly binary tree jis ke saare leaves level d par hon... practically: saare levels poori tarah bhare hon, aakhri level left se bharta hai. (Handout ki exact definition: strictly binary tree all of whose leaves are at level d.) - Full binary tree: har level completely bhara hua.

Properties (numbers walay sawal aate hain): - Level L par zyada se zyada nodes = 2^L (level 0 se ginna). - Height/depth h walay binary tree mein zyada se zyada nodes = 2^(h+1) − 1. - Leaves aur internal nodes (strictly binary tree): leaves = internal nodes + 1.

Applications: expression trees, searching (BST), file system, decision trees. Binary tree mein duplicates search wala topic (Lecture 12): tree mein repeated values dhoondna traversal se hota hai.

C++ implementation: Node class jismein data + left pointer + right pointer; insert node ko tree mein lagata hai (trace practice karo — Lecture 12 mein insert ka trace diya hai).

Exam traps: - Binary tree ≠ BST. Aam binary tree mein values ka koi order nahi hota; order wala BST hai (agla topic). - Ek child walay node mein "left ya right" ka farq binary tree mein count hota hai — do mukhtalif trees bante hain.

12. Binary Search Tree (BST) (Lectures 12–13)

Definition / BST property: Har node ke liye: - Left subtree ki saari values node ki value se chhoti - Right subtree ki saari values node ki value se bari - Dono subtrees khud bhi BST hain.

Search: Root se shuru karo. Value == node → mil gaya. Value chhoti → left jao. Value bari → right jao. NULL par pohanchay to value maujood nahi.

search(x, node):
  if node == NULL: return NOT FOUND
  if x == node.data: return FOUND
  if x < node.data: search(x, node.left)
  else: search(x, node.right)

Insert: Pehle search ki tarah neeche jao; jahan NULL mile wahan naya node laga do (hamesha leaf banta hai). Duplicate value aam tor par insert nahi karte (ya ek taraf bhej dete hain — handout duplicates ko alag handle karta hai).

Cost of search (Lecture 13 — bohat important): - Search ki cost = jitne nodes compare hue = tree ki height par depend. - Balanced tree: height ≈ log₂(n) → search O(log n). - Degenerate (skewed) tree: height = n → search O(n) — bilkul linked list jaisa! - Sorted data ko seedha insert karne se degenerate tree banta hai (har naya element sab se bara → sirf right children). Yehi masla AVL tree solve karta hai.

Worked example: Insert 50, 30, 70, 20, 40 → root 50; 30 left, 70 right; 20 → 30 ka left; 40 → 30 ka right. Search 40: 50 → 30 → 40 = 3 comparisons.

Exam traps: - BST ki inorder traversal hamesha sorted order deti hai (agle topic mein hai — ye link wala sawal bohat aata hai). - Insert hamesha leaf par hota hai, beech mein kabhi nahi.

13. Tree Traversals (Lectures 13–15)

Traversal = har node ko exactly ek dafa visit karna. 4 tareeqay:

Traversal Order Yaad rakhne ka tareeqa
Preorder Root → Left → Right Root pehle
Inorder Left → Root → Right Root darmiyan mein
Postorder Left → Right → Root Root aakhir mein
Level-order Level by level, left to right Queue use hoti hai (BFS)

Recursive code (teenon ek jaise, sirf root-visit ki position badalti hai):

inorder(node):
  if node == NULL: return
  inorder(node.left)
  print(node.data)        // preorder mein ye line sab se pehle, postorder mein sab se aakhir
  inorder(node.right)

Non-recursive traversal: Recursion ke baghair stack use karke hota hai (Lecture 14) — function call stack ki jagah apna stack. Exam mein aksar poochte hain: "non-recursive inorder mein stack kab push/pop hota hai" — trace: left jaate hue nodes push karo; NULL aaye to pop karke print karo, phir us ke right par jao.

Level-order traversal: Queue use hoti hai: root enqueue karo; loop: dequeue karke print karo, us ke left/right children enqueue karo. (Lecture 15)

Worked example — tree: root 50, left 30 (children 20, 40), right 70: - Preorder: 50, 30, 20, 40, 70 - Inorder: 20, 30, 40, 50, 70 ← sorted! (BST hai is liye) - Postorder: 20, 40, 30, 70, 50 - Level-order: 50, 30, 70, 20, 40

Exam points / traps (traversal midterm ka sab se pakka topic hai): - Diya gaya tree → chaaron traversals likhna. Practice lazmi. - Inorder of BST = ascending sorted order. Ye property bohat dafa poochi jati hai. - Preorder + inorder se original tree wapas banaya ja sakta hai (unique) — concept yaad rakho. - Level-order mein stack nahi, queue lagti hai — ye farq trap hai.

14. Deleting a Node from BST (Lectures 15–16)

Delete ke teen cases — ye poora topic ek hi sawal ki shakal mein aata hai:

Case 1 — Leaf node (koi child nahi): Bas node delete kar do, parent ka pointer NULL kar do. Asaan tareen.

Case 2 — Ek child hai: Node ko hata kar us ke ek hi child ko parent se seedha jor do (child node ki jagah "promote" ho jata hai). Bilkul linked list wale delete jaisa.

Case 3 — Do children hain (mushkil case): Node ki value ko replace karo: - Us ke right subtree ke sab se chhote node (inorder successor) se — ya left subtree ke sab se bare node (inorder predecessor) se. - Phir jis node se value copy ki thi, usay delete karo — woh hamesha Case 1 ya Case 2 mein hota hai (successor ke left child nahi hota).

delete(x):
  find node
  if leaf: remove
  else if one child: replace node with that child
  else: copy inorder-successor's value here; delete successor node

Worked example: Upar walay tree (50, 30, 70, 20, 40) se 30 delete karo → 30 ke do children (20, 40) hain → successor = right subtree (40) ka sab se chhota = 40 → 30 ki jagah 40 likho, purana 40 wala leaf delete kar do. Naya tree: 50 ke left = 40, us ka left = 20. ✔

Exam traps: - Case 3 mein node physically delete nahi hota pehle — pehle value copy hoti hai, delete successor hota hai. - Successor = right subtree ka leftmost node. Predecessor = left subtree ka rightmost node. Ulta mat karna.

15. Degenerate BST & AVL Trees (Lectures 19–22)

Degenerate BST: Sorted (ya reverse sorted) data insert karne se tree ek seedhi line ban jata hai — har node ka sirf ek child. Search O(n) ho jata hai; tree ka faida khatam. Solution: khud ko balance rakhne wala tree — AVL.

AVL Tree: Ek BST jo har node par balance check rakhta hai (Adelson-Velsky & Landis ke naam par). - Balance factor of a node = height(left subtree) − height(right subtree). - AVL mein har node ka balance factor sirf −1, 0, ya +1 ho sakta hai. Is se bahir jaye to tree "unbalanced" — rotation se theek karte hain. - Faida: height hamesha O(log n) rehti hai → search/insert/delete sab O(log n) guaranteed.

Insertion: Pehle aam BST insert karo. Phir wapas root ki taraf jate hue har ancestor ka balance factor check karo. Pehla node jahan balance ±2 ho jaye, wahan rotation lagao. Sirf ek (single ya double) rotation se poora tree dobara balance ho jata hai.

The 4 cases (rotation selection — ye table ratta kar lo):

Case Problem ki shakal Fix
Case 1: Left-Left (LL) Insertion left subtree ke left mein hui Single right rotation
Case 4: Right-Right (RR) Insertion right subtree ke right mein hui Single left rotation
Case 2: Left-Right (LR) Insertion left subtree ke right mein hui Double rotation: pehle left rotation (child par), phir right rotation
Case 3: Right-Left (RL) Insertion right subtree ke left mein hui Double rotation: pehle right rotation (child par), phir left rotation

Yaad rakhne ka rule: Insertion jis "zigzag" shakal mein hui (LR ya RL) wahan double rotation; seedhi shakal (LL ya RR) wahan single rotation — aur rotation hamesha unbalanced node ko neeche dhakel kar us ke child ko upar lati hai.

Worked example (LL): Insert 30, 20, 10 → 30 ka balance = +2 (left height 2, right 0) → LL case → right rotation on 30 → naya root 20, left 10, right 30. Balanced ✔ Worked example (LR): Insert 30, 10, 20 → 30 ka balance +2 lekin insertion left child (10) ke right mein hui → pehle 10 par left rotation (20 upar aata hai), phir 30 par right rotation → root 20, left 10, right 30 ✔

C++ avlInsert: recursive insert; wapas aate hue height/balance update, zaroorat paray to rotation; handout mein poora code Lecture 22 mein hai — steps ka concept samajhna code ratne se zyada important hai.

Exam points / traps: - Balance factor ki definition mein left − right hai (kuch books right − left likhte hain — VU handout left − right use karta hai; sign ulta karoge to case ulta ho jayega). - Rotation ke baad BST property kharab nahi hoti — inorder traversal rotation se pehle aur baad same rehta hai. Ye ek khoobsurat exam point hai. - AVL mein delete ke baad multiple rotations lag sakti hain (insert mein sirf ek jagah) — lekin delete ka detailed rotation midterm handouts mein kam emphasize hai; insert par focus rakho. - Har rotation O(1) hai — sirf chand pointers badalte hain.

16. Master Big-O Table (sab ek jagah)

Structure Access Search Insert Delete Note
Array O(1) O(n) O(n) O(n) insert/delete par shifting
Array List (end par) O(1) O(n) O(1) O(1) jagah ho to
Singly Linked List O(n) O(n) O(1)* O(1)* *position/address maloom ho to
Stack (array ya list) top O(1) — push O(1) pop O(1) sirf top accessible
Queue (circular array / list) front O(1) — enqueue O(1) dequeue O(1) circular mein modulo
Priority Queue (list) — — O(1) ya O(n) O(n) ya O(1) unsorted vs sorted list ka trade-off
BST (balanced) — O(log n) O(log n) O(log n) height par depend
BST (degenerate) — O(n) O(n) O(n) sorted input ki saza
AVL Tree — O(log n) O(log n) O(log n) hamesha balanced — guaranteed

17. Last-Minute Checklist (paper se pehle)

  • [ ] Stack = LIFO, Queue = FIFO — operations ke naam (push/pop, enqueue/dequeue) ke saath.
  • [ ] Infix → postfix conversion aur postfix evaluation ke 2–2 trace haath se karke dekho.
  • [ ] Linked list insert/delete ke pointer steps sahi order mein (pehle newNode->next, phir p->next).
  • [ ] Circular queue ka (index + 1) % size aur full/empty ka masla.
  • [ ] Ek diye gaye tree ke chaaron traversals (pre/in/post/level) likhne ki practice.
  • [ ] BST delete ke 3 cases — khaas kar do-children wala (successor copy + successor delete).
  • [ ] AVL: balance factor = left height − right height; 4 cases aur un ke rotations wali table.
  • [ ] Degenerate BST banta kaise hai (sorted insert) aur AVL usay kaise rokta hai.
  • [ ] Definitions: ADT, leaf, depth, height, complete/strictly binary tree, LIFO/FIFO, overflow/underflow.
  • [ ] Big-O table upar wala — kam az kam har structure ki search/insert/delete cost.
